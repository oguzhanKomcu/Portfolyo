C# 14 ile Extension Property: Yıllardır Eksik Olan Parça

C# 14'ün yeni extension bloğu ile değiştiremediğiniz sınıflara property ve static üye eklemek.

Extension metotlar C#'ın en sevilen özelliklerinden biri. LINQ'in tamamı zaten bunun üzerine kurulu. Ama hep bir sınırı vardı: sadece metot yazılabiliyordu.

Bir müşterinin tam adını almak için "customer.FullName" yazmak çok daha doğal dursa da, mecburen "customer.GetFullName()" yazılıyordu. Anlam olarak bir property, ama yazım olarak bir metot.

Senaryo: değiştiremediğimiz bir sınıf

Extension'ların asıl kullanım amacı, kaynak koduna dokunamadığımız sınıflara dışarıdan özellik eklemek. Örneğin başka bir kütüphaneden gelen bir Customer modeli:

// 📦 Başka bir kütüphaneden gelen model, kaynak koduna dokunamıyoruz
public class Customer
{
    public string FirstName { get; set; } = string.Empty;
    public string LastName { get; set; } = string.Empty;
    public DateTime BirthDate { get; set; }
    public List<Order> Orders { get; set; } = [];
}

Önce: her şey metot

Eski yöntemde her extension ayrı bir metot ve her birinde "this Customer customer" parametresi tekrar tekrar yazılıyor:

public static class CustomerExtensions
{
    public static string GetFullName(this Customer customer)
        => $"{customer.FirstName} {customer.LastName}";

    public static bool HasOrders(this Customer customer)
        => customer.Orders.Count > 0;
}

Console.WriteLine(customer.GetFullName());
if (customer.HasOrders()) { /* ... */ }

C# 14: extension bloğu

C# 14 ile gelen "extension" bloğunda tip başta bir kez tanımlanıyor. Bloğun içine property, metot ve static üye yazılabiliyor:

public static class CustomerExtensions
{
    extension(Customer customer)
    {
        public string FullName => $"{customer.FirstName} {customer.LastName}";
        public bool HasOrders => customer.Orders.Count > 0;

        public int Age
        {
            get
            {
                var today = DateTime.Today;
                var age = today.Year - customer.BirthDate.Year;
                // Doğum günü bu yıl henüz gelmediyse bir yaş eksik
                if (customer.BirthDate.Date > today.AddYears(-age)) age--;
                return age;
            }
        }

        // Static üye: sanki Customer sınıfının kendisinde varmış gibi
        public static Customer Guest => new() { FirstName = "Misafir", LastName = "Kullanıcı" };
    }
}

Console.WriteLine(customer.FullName);           // sanki sınıfın kendi property'si
if (customer.Age >= 18 && customer.HasOrders) { /* ... */ }

var guest = Customer.Guest;                     // static extension
GetFullName() artık FullName. Küçük bir fark gibi görünüyor ama kod, sınıfın kendi üyesini kullanıyormuş gibi okunuyor.

Neler kazanılıyor?

  • Property'ler: customer.FullName, customer.Age
  • Static üyeler: Customer.Guest, sanki tipin kendisinde varmış gibi
  • Tekrar yok: tip bloğun başında bir kez tanımlanıyor
  • Düzen: aynı tipe ait tüm extension'lar tek bir yerde toplanıyor

Eski kodlar ne olacak?

Hiçbir şey. "this" ile yazılmış eski extension metotlar çalışmaya devam ediyor. Mevcut kodu değiştirmek zorunlu değil, istenirse yavaş yavaş yeni yapıya taşınabiliyor.

Bilinmesi gereken tek sınır

Extension property'ler veri saklayamıyor. Yani bir tipe dışarıdan yeni bir alan eklenemiyor, sadece var olan veriden hesaplanan değerler yazılabiliyor: FullName, Age, HasOrders gibi.

Bu özellik C# 14 ile geldi, kullanmak için .NET 10 SDK gerekiyor.
